# Модель авторизации

> kubernetes-finops-platform · мессенджер, часть 8

Матрица прав, переходы состояний и инварианты. Документ строится не от
обработчиков HTTP, а от отношения

```
СУБЪЕКТ × РЕСУРС × ДЕЙСТВИЕ × УСЛОВИЯ → РАЗРЕШИТЬ | ОТКАЗАТЬ
```

Причина в том, что одно и то же право проверяется в четырёх разных местах:
в обработчике REST, при выдаче токена Centrifugo, в потребителе, рассылающем
уведомления, и в админской операции. Если правило описано у каждого из них
своими словами, они разойдутся — и разойдутся молча, потому что расхождение
видно только на том запросе, который никто не пробовал.

## Часть 1. Субъекты, ресурсы, действия

### Субъекты

| Субъект | Кто это |
| --- | --- |
| `anonymous` | без действительного токена |
| `user` | вошедший пользователь вообще |
| `member` | действующий участник конкретной беседы |
| `former-member` | вышел или исключён, `left_at` проставлен |
| `blocker` | заблокировал другого пользователя |
| `blocked` | заблокирован другим пользователем |
| `support` | сотрудник поддержки |
| `moderator` | разбирает жалобы |
| `admin` | административные операции |
| `service` | внутренний сервис по своей учётной записи |

`member` — не роль пользователя, а отношение к ресурсу. Один и тот же человек
`member` в одной беседе и `anonymous` по отношению к соседней.

### Ресурсы и действия

```
User          read · update · disable · erase
Session       read · revoke
Conversation  create · read · write · leave
Message       create · read · delete · moderate
Attachment    create · download · delete
Presence      read
Typing        publish · subscribe
Report        create · read · resolve
AdminAction   execute
```

## Часть 2. Матрица прав

Условие в последнем столбце — не пояснение, а само правило. Пустое условие
означает безусловное разрешение.

### Беседа и сообщения

| Субъект | Ресурс | Действие | Условие |
| --- | --- | --- | --- |
| `member` | Conversation | `read` | `left_at IS NULL` |
| `former-member` | Conversation | `read` | только история до `left_at` |
| `non-member` | Conversation | `read` | **отказать** — включая прямую ссылку по идентификатору |
| `member` | Conversation | `write` | `left_at IS NULL` И собеседник не заблокировал |
| `member` | Message | `create` | членство из источника истины, не из кеша |
| `member` | Message | `read` | членство И `seq ≤` последнего доступного |
| `sender` | Message | `delete` | своё сообщение, срок не истёк |
| `member` | Message | `delete` | **отказать** — чужое сообщение не удаляется |
| `user` | Conversation | `create` | собеседник не заблокировал инициатора |

### Присутствие и набор

| Субъект | Ресурс | Действие | Условие |
| --- | --- | --- | --- |
| `member` | `conversation:{id}` | `subscribe` | действующее членство на момент выдачи токена |
| `non-member` | `conversation:{id}` | `subscribe` | **отказать** |
| `member` | `typing:{id}` | `publish` | членство И предел частоты |
| `non-member` | `typing:{id}` | `publish` | **отказать** |
| `user` | Presence | `read` | есть общая беседа с наблюдаемым |
| `blocked` | Presence заблокировавшего | `read` | **отказать** |

### Блокировка

Самая тонкая часть, потому что блокировка асимметрична и не является удалением.

| Субъект | Ресурс | Действие | Решение |
| --- | --- | --- | --- |
| `blocked` | беседа с `blocker` | `write` | отказать |
| `blocked` | беседа с `blocker` | `read` старой истории | **разрешить** |
| `blocked` | Presence `blocker` | `read` | отказать |
| `blocked` | Typing `blocker` | `read` | отказать |
| `blocked` | новая беседа с `blocker` | `create` | отказать |
| `blocker` | беседа с `blocked` | `read` и `write` | разрешить |

**Почему старая история остаётся видна.** Блокировка — отказ от будущего
общения, а не стирание прошлого. Скрыть уже прочитанное невозможно
технически — оно на устройстве, — а попытка скрыть создаёт ложное обещание
приватности. Решение принято и записано, чтобы его не пересматривали каждый раз,
когда о нём спрашивают.

### Вложения

| Субъект | Ресурс | Действие | Условие |
| --- | --- | --- | --- |
| `user` | Attachment | `create` | предел частоты И предел объёма |
| `user` | Attachment | `download` | право на **родительскую беседу**, а не на само вложение |
| `former-member` | Attachment | `download` | вложение из истории до `left_at` |
| `anonymous` | Attachment | `download` | **отказать** — подписанная ссылка не заменяет проверку |

Право на вложение производно от права на беседу. Иначе идентификатор вложения,
попавший в журнал или в историю браузера, становится доступом к чужому файлу.

### Поддержка, модерация, администрирование

| Субъект | Ресурс | Действие | Условие |
| --- | --- | --- | --- |
| `support` | User | `read` | профиль и метаданные, **без содержимого сообщений** |
| `support` | Message `content` | `read` | **отказать по умолчанию** |
| `moderator` | Report | `read` и `resolve` | аудит каждой операции |
| `moderator` | Message пожалованное | `read` | только конкретное сообщение из жалобы |
| `admin` | User | `disable` | второй фактор И аудит |
| `admin` | Session | `revoke` | второй фактор И аудит |
| `admin` | Message | `read` в обход | **отказать** — обхода не существует |

**Поддержка не читает переписку.** Это решение, а не недоработка: как только
чтение возможно «по уважительной причине», оно происходит. Модератор видит
ровно то сообщение, на которое поступила жалоба, — не беседу и не историю.

## Часть 3. Переходы состояний

Права — не статическая таблица. Опаснее всего именно моменты перехода.

### Членство

```
   вступил
      │
      ▼
   member ──── исключён или вышел ───▶ former-member
      │                                     │
      │                          читает историю до left_at
      │                          писать не может
      │                          подписка на канал рвётся
      ▼
   удалён из системы
```

**Исключение обязано разорвать подписку немедленно.** Если исключённый остаётся
подписанным на канал беседы, он продолжает получать новые сообщения, и это уже
не устаревший кеш, а утечка. Путь отзыва описан в [части 1](01-architecture.md):
`membership.removed` через Kafka → сброс кеша → отписка → разрыв соединения.

### Блокировка

```
   обычные отношения
      │ A блокирует B
      ▼
   B не пишет A
   B не видит присутствие A
   B не видит набор A
   B видит старую переписку
   B не создаёт новую беседу с A
      │ A снимает блокировку
      ▼
   обычные отношения
```

### Сессия

```
   активная сессия
      │
      ├── истёк срок токена ──────▶ отозвана отложенно
      │
      ├── выход на устройстве ────▶ отозвана немедленно (одна)
      │
      ├── выход везде ────────────▶ отозваны немедленно (все)
      │
      ├── смена пароля ───────────▶ отозваны немедленно (все)
      │
      └── отключение админом ─────▶ отозваны немедленно (все)
              │
              ▼
      событие доходит до Centrifugo
              ▼
      соединения WebSocket разорваны
```

Отложенный и немедленный отзыв устроены по-разному, и это отдельная задача
`G1-008`. Немедленный требует собственного пути доставки события: срок жизни
токена ждать нельзя, иначе «выйти на всех устройствах» ничего не гарантирует
ближайшие минуты.

## Часть 4. Инварианты

Проверяются автоматически и не обсуждаются на ревью.

### И-1. Устаревшее состояние никогда не расширяет права

Центральный инвариант всей модели.

```
кеш говорит РАЗРЕШИТЬ, база говорит ОТКАЗАТЬ   →  ОТКАЗАТЬ
кеш говорит ОТКАЗАТЬ,  база говорит РАЗРЕШИТЬ  →  допустимо (отказ безопасен)
```

Отсюда разное отношение к кешу для чтения и для записи:

| | Кеш членства |
| --- | --- |
| **Чтение** | допустим ограниченный по времени устаревший кеш |
| **Запись** | недопустим; членство читается из источника истины |
| **Выдача токена подписки** | недопустим |
| **Отзыв доступа** | применяется немедленно, не по истечении TTL |

Асимметрия сознательная: ошибка в сторону отказа стоит одного повтора запроса,
ошибка в сторону разрешения стоит доступа к чужой переписке.

### И-2. Отсутствие права неотличимо от отсутствия ресурса

```
чужая беседа по прямому идентификатору  →  404, не 403
```

`403` подтверждает, что беседа существует. Перебором идентификаторов так
выясняется, кто с кем переписывается, — без единого прочитанного сообщения.

Исключение: там, где субъект заведомо знает о существовании ресурса
(собственная беседа, из которой он вышел), `403` допустим и понятнее.

### И-3. Проверка на сервере, всегда

Клиент не выбирает канал подписки — сервер выдаёт токен с явным списком.
Подписанная ссылка не заменяет проверку прав. Скрытая в интерфейсе кнопка
не является запретом.

### И-4. Право на производный ресурс выводится из родительского

Вложение — из беседы. Квитанция о прочтении — из членства. Собственного списка
прав у производного ресурса нет: два независимых списка расходятся.

### И-5. Привилегированное действие оставляет след

Любая операция `support`, `moderator` или `admin` пишет запись в поток `audit`
со сроком хранения больше, чем у обычных журналов. Операция без аудита
считается несовершённой.

## Часть 5. Где это проверяется в коде

По [инженерному стандарту](07-engineering-standard.md) авторизация живёт
в сервисном слое, а не в обработчиках.

```python
async def authorize(
    conn: Connection,
    *,
    subject: SubjectId,
    resource: ResourceRef,
    action: Action,
    freshness: Freshness = Freshness.AUTHORITATIVE,
) -> Decision:
    """Единственная точка принятия решения.

    freshness=CACHED допустим только для чтения. Для записи, выдачи токена
    подписки и любой привилегированной операции — только AUTHORITATIVE:
    инвариант И-1 запрещает расширять права по устаревшим данным.
    """
```

Обработчик не проверяет права сам — он вызывает `authorize` и переводит
`Decision` в код ответа. Потребитель Kafka вызывает ту же функцию. Причина
в первом абзаце документа: четыре реализации одного правила разойдутся.

Отказ записывается в журнал с кодом из таксономии ошибок и попадает в метку
`error_class` метрики — иначе всплеск отказов в правах неотличим от всплеска
любых других `4xx`.

| Заблокированный пишет | `BLK-001` |
| Заблокированный смотрит присутствие | `BLK-002` |
| Заблокированный создаёт беседу | `BLK-003` |

| Жалоба доходит до человека | `RPT-001` |
| Поддержка открывает содержимое | `ADM-002` |

| Обновление токена после отзыва | `AUTH-004` |
| Вложение без прав на беседу | `ATT-006` |
| Присутствие и его срок | `PRS-001…003` |

### Чего в каталоге ещё нет

Правила ниже описаны здесь, но приёмочного теста под них не заведено. Это
означает не пробел документа, а задачу в каталог:

| Правило | Нужен тест |
| --- | --- |
| Вышедший читает историю до `left_at`, но не позже | `AUTHZ-001` |
| Исключение немедленно рвёт подписку | `AUTHZ-002` |
| Устаревший кеш не расширяет права (И-1) | `AUTHZ-003` |
| Отказ выглядит как отсутствие ресурса (И-2) | `AUTHZ-004` |
| Привилегированная операция оставляет аудит (И-5) | `AUTHZ-005` |

`AUTHZ-003` — важнейший из пяти: он проверяет центральный инвариант, и
проверяется он единственным способом — изменить членство в базе, не сбрасывая
кеш, и убедиться, что запись отклонена.

## Что этот документ блокирует

Модель базы данных G1 не объявляется стабильной, пока не закрыты эта часть и
[жизненный цикл данных](09-data-lifecycle.md). Причина простая: `former-member`,
границы видимости истории и аудит привилегированных операций — это колонки
и индексы, а не логика поверх готовой схемы.
