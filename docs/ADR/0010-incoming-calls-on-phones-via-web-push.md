# ADR 0010: Входящие звонки на телефонах идут двумя независимыми путями, вторым — Web Push

## Статус

Предложен

Дополняет [ADR 0007](0007-calls-after-web-push.md) и [ADR 0009](0009-resilient-access-and-guest-calls.md). Номер 0008 занят под поиск контактов.

## Контекст

Звонок 1:1 доходит до вызываемого одним путём: `call.incoming` → Centrifugo (WebSocket) → открытая страница → рингтон. Если Vector на
телефоне не открыт, страница выгружена или экран заблокирован, сокета нет, и звонок **не слышен**. Хуже того, он не начинается:
«вызываемый достижим» значит «есть живое соединение звонков», и звонящему сразу отвечают `unavailable`. Спящий телефон выглядит как
выключенный. Web Push в проекте есть, но только для сообщений (Service Worker на любой push показывает «New message», сервер шлёт его
из `consumer-notifications` по outbox сообщений).

Нативного приложения нет и не планируется (ADR 0000, [часть 18](../messenger/18-resilient-access-and-guest-calls.md)): браузер не
даёт системного входящего звонка, только уведомление.

## Решение

1. **Два независимых пути доставки, запускаются одновременно.** Открытая страница получает звонок по Centrifugo (быстро, с рингтоном),
   спящий телефон — по Web Push (системное уведомление). Дубль схлопывается тегом уведомления `call:<call_id>`.
2. **Достижимость вызываемого** — живое соединение звонков **или** push-подписка. Нет ни того, ни другого — `unavailable`, как сейчас.
3. **Намерение отправить push durable.** Запись `call_push_outbox(call_id, recipient_id, event, expires_at)` делается **в той же
   транзакции**, что создаёт (и завершает) звонок; отправляет отдельный быстрый воркер с короткими повторами до `expires_at`, не Kafka-
   конвейер сообщений. Публикация «после `COMMIT`» без записи намерения оставляла бы окно «звонок `ringing` есть, а push не уйдёт».
4. **Заголовки push.** `Urgency: high`, `TTL` не больше окна звонка, `Topic` — **не длиннее 32 символов base64url** (RFC 8030; UUID с
   дефисами даёт `400`): `base64url(HMAC(ключ_темы, call_id))[:22]`, так `call_id` не уходит открытым (`Topic` не шифруется).
5. **Имя звонящего скрыто по умолчанию.** Уведомление — «Incoming audio call» / «Incoming video call»; имя показывается, если человек
   включил «Show caller names in notifications». Нагрузка шифруется (RFC 8291), угроза — экран блокировки. Нагрузка несёт `caller_name`,
   выбор делает Service Worker по локальной настройке.
6. **Окно звонка.** Достижимому только через push — **60 с**, при живом сокете остаётся 30 с (определяется при создании). Автопродления
   нет; если на настоящих телефонах не хватит — один явный `POST /calls/{id}/wake` до 90 с от `created_at`. `GET` состояния не меняет.
7. **Уведомление — один автомат** (общие `Topic` и тег): «Incoming call», «Call cancelled», «Missed call», «Call answered on another
   device». Каждое событие показывает уведомление (на iOS молчаливый push запрещён). Схема «показать и закрыть» не используется.
8. **Push не доверяется.** Нажатие → открыть Vector → `GET /calls/current` → если `ringing`, «Принять / Отклонить»; иначе «Звонок
   завершён». Принимающая страница забирает сигналы через `GET /calls/{id}/signals?after=`, не ожидая сокета.
9. **iPhone — только приложение на экране «Домой»** (iOS 16.4+). Без установки звонки при закрытом приложении не доходят; интерфейс
   показывает это явно (панель готовности, `CALL-019`), а не молчит.
10. **Включение для людей — после `CALL-017`** (блокировка, лимит) и исправной подписки Web Push (`G4-023`, P1 про точку `p256dh`).

## Отвергнутые альтернативы

| Вариант | Почему нет |
| --- | --- |
| Только WebSocket (как сейчас) | спящий телефон не слышит звонок и считается «не в сети» |
| Push после `COMMIT` без записи намерения | сбой процесса оставляет звонок `ringing` без уведомления |
| Push через Kafka-конвейер сообщений | задержка и очередь сообщений; звонок живёт 30–60 с |
| `Topic = call_id` (UUID) | 36 символов, служба push отвечает `400` |
| Имя звонящего по умолчанию | утечка людям рядом на экране блокировки |
| Автопродление окна по `GET /calls/current` | GET меняет состояние, гонки автомата |
| Беззвучный push и «показать и сразу закрыть» на iOS | нарушает `userVisibleOnly`, подписка отзывается; вспышка уведомления |
| Нативное приложение с системным звонком | вне объёма: браузерный продукт, другая архитектура |

## Последствия

- Уведомление — не системный входящий звонок: звук задаёт ОС, режимы «Не беспокоить» и «Фокус» его глушат, на Android энергосбережение
  может задерживать push, на iPhone без установки уведомлений нет. Полноэкранного звонка как у нативных мессенджеров не будет.
- Появляются таблица `call_push_outbox`, воркер и метрики `messenger_call_push_total{result}`; миграция по правилам
  [ADR 0006](0006-expand-contract-migrations.md).
- Push зависит от сторонних служб (FCM, APNs, автопуш): если они недоступны, остаётся путь через WebSocket.
- Приёмка на настоящих телефонах — ручная (`CALL-020`); сервер и Service Worker проверяются автоматикой (заглушка push-сервиса,
  `ServiceWorker.deliverPushMessage`).
