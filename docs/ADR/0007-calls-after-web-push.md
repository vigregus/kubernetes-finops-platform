# ADR 0007: Звонки один-на-один идут сразу после Web Push

## Статус

Принято

Уточняет [ADR 0000](0000-v1-scope.md): звонки перестают быть «вне
проекта» и получают место в порядке работ. Остальные исключения ADR 0000
(шифрование, оплата, группы) остаются в силе.

## Контекст

ADR 0000 исключил «голосовые и видеозвонки» из v1 и оговорил: возврат любой
отложенной возможности — это новый ADR с собственным обоснованием.

Оценка [части 16](../messenger/16-calls-estimate.md) показала:

- звонок один-на-один можно построить **без SFU**: медиа идёт напрямую между
  браузерами, а сервер делает сигнализацию, выдаёт доступ к TURN и пишет
  итог в ленту;
- это ≈ 63 рабочих дня, из них почти половина — браузерная часть и её
  проверка;
- стоимость при 5% звонящих в сутки — порядка $1 тыс. в месяц с управляемым
  TURN против ≈ $19 250 всего счёта; главная статья — релей TURN, а не серверы;
- звонок без Web Push слышит только открытая вкладка.

## Решение

1. **Звонки один-на-один (аудио и видео) входят в план.** Групповые звонки,
   демонстрация экрана и запись остаются вне плана.
2. **Порядок: сразу после Web Push** (`NTF-001…004`), в рамках G4. Бэклог —
   `CALL-001…012` в [мастер-плане](../../IMPLEMENTATION-PLAN.md), тесты —
   `CALL-001…016`.
3. **Без SFU.** Прямой WebRTC плюс TURN. LiveKit откладывается до групповых
   звонков.
4. **TURN за интерфейсом `TurnProvider`.** Начинаем с управляемого
   (Cloudflare); свой coturn — запасной вариант, а не стартовый.
5. **Сигнализация — через API.** Клиент не публикует в Centrifugo; сигналы идут
   в канал без истории, с `call_id` и монотонным `seq`.
6. **Состояние звонка живёт на сервере**, итог пишется системным сообщением
   в той же транзакции.
7. **Блокировок на этом этапе нет** (решение владельца): звонить можно
   участнику беседы, остальное не проверяется.

### Что остаётся открытым и решается до включения для людей

| Вопрос | Почему важен |
| --- | --- |
| Матрица поддерживаемых браузеров (Safari, мобильные) | +10–30 дней и ручное тестирование |
| Прямое соединение или только релей | прямое показывает IP участников; релей дороже до ×6,7 |
| Нежелательные звонки без блокировок | нечем остановить; минимум — лимит попыток (+2 дня) |

Разработка идёт под флагом `calls_enabled`; включение для людей — после этих
решений.

## Отвергнутые альтернативы

| Альтернатива | Почему нет |
| --- | --- |
| LiveKit (SFU) сразу | для 1:1 не нужен; добавляет пул узлов и отказы, которых нет у прямого соединения |
| Свой coturn сразу | при любой нагрузке дороже Cloudflare по исходящему трафику, плюс эксплуатация; остаётся запасным |
| Twilio TURN | $0,40/ГБ — в восемь раз дороже Cloudflare |
| Только релей по умолчанию | до ×6,7 к стоимости; остаётся опцией приватности |
| Звонки до Web Push | офлайн-пользователь не узнаёт о звонке; возможно только как разработка под флагом |

## Последствия

- Формулировка продукта меняется только после включения флага для людей;
  до тех пор верна формулировка ADR 0000.
- `01-architecture.md` называет LiveKit и coturn целевой схемой; для 1:1 это
  больше не так, пересмотр — в `CALL-012`.
- Модель затрат ([часть 10](../messenger/10-cost-model.md)) получает строку
  про релей TURN; утверждение «звонки: медиатрафик на порядки больше файлового»
  верно только для SFU.
- Допущения оценки (доля релея 15%, битрейт 1 Мбит/с) проверяются метрикой
  `messenger_call_connection_type_total` в первую неделю после включения.
