# Правила работы в репозитории

## Pull request

- Одна фича — один PR: фичу можно протестировать целиком до мержа в `main` и откатить одним коммитом.
  Не дроби фичу на атомарные PR, которые по отдельности ничего не дают.
- Перед мержем фича проверяется на стенде из ветки (предпросмотр через ArgoCD), а не только тестами.

## Тесты (в том числе при работе через скилл `tdd`)

- Backend: синхронные тесты, асинхронный код через `asyncio.run`, без `pytest-asyncio`.
- Репозитории подменяются через `monkeypatch`; имена тестов на русском.
- Слои проверяет `scripts/check-layers.py` (api не импортирует adapters), каталог логов — `scripts/check-log-streams.py`,
  миграции — `scripts/check-migrations.py`.
- Проверка на живых Postgres/MinIO — `tests/integration/`; браузерная приёмка — `scripts/web-e2e-fixture.sh`.

## ADR и глоссарий (при работе через скилл `domain-modeling`)

- ADR лежат в `docs/ADR/`, нумерация продолжается после последнего номера (сейчас `0006`).
  Структура и язык — как в существующих (`Статус`, `Контекст`, `Решение`, …), русский текст; формат из скилла не навязывать.
- Глоссарий и ADR пишутся по-русски, технические термины и идентификаторы остаются как в коде.

## Прочее

- Работай по `IMPLEMENTATION-PLAN.md`: после завершения шага обновляй статус в таблице бэклога.
- Коммиты без трейлера `Co-Authored-By`.
