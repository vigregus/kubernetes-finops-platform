# argocd-image-updater

Выкатка мессенджера следует за последним собранным образом **без коммита в git**.

## Как это устроено

Апдейтер раз в две минуты спрашивает реестр о тегах, выбирает подходящий и
патчит **живой** `Application messenger-services` через API кластера
(`writeBackConfig.method: argocd`). Файл в git при этом не меняется — ни
`values.yaml`, ни `Application`. Это и есть требование: продвижение не требует
человека с коммитом.

Установка — из апстрима по тегу `v1.3.0` (`config/install.yaml`: CRD, RBAC,
Deployment). В репозиторий чужой манифест не вендорится: он устаревает молча,
а тег видно и он же откатывается сменой одной строки.

## Что именно берётся

* **Стратегия `newest-build`** — тег, опубликованный позже всех. Не «старший по
  номеру»: номеров у нас нет, а `:latest` и `:main` не заводятся вовсе —
  подвижный тег возвращает ровно ту проблему, ради которой всё это делается.
* **Отбор `allowTags: "regexp:^[0-9a-f]{40}$"`** — сорок шестнадцатеричных
  знаков, то есть sha коммита. Это отбор **формы**, а не ветки: образы собираются
  из любой ветки (`.github/workflows/image.yml`), и тег у них одинаков — по нему
  merge от незамерженного коммита не отличить. Значит «последний» может быть
  образом из ветки; цена названа ниже.
* **Пять нагрузок — один образ**: `api`, `outbox-relay`, `consumer-realtime`,
  `consumer-unread`, `presence-sweeper` адресуют `messenger-api`; `web` — свой
  `messenger-web`. Все шесть записей идут одним списком, и это не подробность:
  разные теги у нагрузок одного образа означали бы, что «выкатили версию»
  больше ничего не значит.

## Куда пишется

Полная ссылка `репозиторий:тег` — в helm-параметр `services.<нагрузка>.image.spec`.
Чарт принимает её как есть и не пересобирает (`charts/messenger/templates/_helpers.tpl`),
а в версию сборки отдаёт тег.

`image.digest` в `values.yaml` при этом остаётся на месте и остаётся путём по
умолчанию: этаж выкатывается по диджесту из git, если апдейтер `Application` не
трогал.

## Чем это платится — названо

1. **Стенд катится сам** — и не только на merge в `main`: сборка идёт из любой
   ветки, тег у неё той же формы, значит push в ветку публикует новый
   «последний» образ, и стенд уезжает на незамерженный код. Разделения
   «выкатили» и «слили» больше нет вовсе.
2. **Нагрузки адресуются тегом, а не диджестом.** Выкатка по тегу — то, против
   чего написан `DEP-001`: тот же тег однажды может означать другие байты.
   Реестр здесь не даёт перезаписать `:<sha>` (это метка коммита), но проверить
   это подписью мы не можем — говорим как есть. И это не выбор настройки:
   диджест апдейтер записать не умеет — `manifestTargets.helm.spec` получает
   `GetFullNameWithTag()`, то есть `репозиторий:тег`, а форма `тег@диджест`
   живёт только в ветке `name`+`tag` и требует стратегии `digest`, которой
   нужен подвижный тег.
3. **Источник истины о текущей выкатке переехал.** Им стал живой `Application`,
   а не `values.yaml`: там последний диджест, продвинутый руками. Закрывая гейт,
   ссылаться на диджест следует из `Application`, а не из файла.
4. **Патч не переносится.** Синк из git или пересоздание `Application` вернут
   значение из `values.yaml` — и следующий же опрос апдейтера поставит свежее
   обратно.

## Почему `selfHeal` его не откатывает

`gitops/01-root/root-application.yaml` — app-of-apps с `selfHeal: true`, и он
владеет дочерними `Application`. Патч апдейтера для него — расхождение с git,
которое он бы откатывал; апдейтер ставил бы снова, и так по кругу. Поэтому в
root объявлен `ignoreDifferences` ровно на
`/spec/sources/1/helm/parameters` `Application messenger-services`.

Цена названа там же: параметры этого источника, заданные в git, тоже перестанут
применяться. Сегодня их нет ни одного — значения приходят через `valueFiles`.
